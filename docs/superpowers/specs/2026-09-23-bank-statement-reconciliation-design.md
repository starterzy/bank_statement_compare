# 银行流水对账工具 — 设计文档

- 日期：2026-09-23
- 状态：待评审

## 1. 目标与范围

做一个本地 Web 工具，把「银行对账单」与「数据库系统银行流水」进行对账：

1. **逐笔对应**：把两边流水一笔笔对上，同时核对**月度发生额**是否一致。
2. **合并记账拆分**：识别系统里「对同一往来方合并记账」的情况，给出拆分并标注。
3. **总结报告**：对比完成后输出总结——月度总额不一致（最严重）> 未匹配项 > 合并记账提示 > 全部对应。

### 首版范围（已确认）

- 只支持 **Excel**（银行对账单 `.xls/.xlsx` + 数据库流水 `.xlsx/.csv`）。
- PDF / PNG 对账单解析放**后续迭代**。
- **数据库导出格式视为确定**：用固定/可配置字段映射，不走 LLM 识别。
- **银行对账单格式不统一**：由 LLM 判断各字段与数据库字段的对应关系。

## 2. 关键决策（已与用户确认）

| 项 | 决策 |
|---|---|
| 交付形态 | 本地 Web 应用（FastAPI 后端 + 原生 HTML/JS 前端，无构建步骤） |
| 字段对应 | **银行对账单**用 LLM（Claude API）判断各字段与数据库字段的对应关系 |
| 输出 | Excel 标注表 + 文字总结 |
| 匹配规则 | **金额优先**，日期**限定在同一月**，**借对借、贷对贷** |
| 方向处理 | **不做方向归一化**，借方、贷方各自独立保留 |
| 月度核对 | 分别统计**月度借方总额**、**月度贷方总额**，借对借、贷对贷比对 |
| 数据库格式 | **视为确定**，用固定/可配置字段映射，不走 LLM |

## 3. 架构

```
上传两个文件（银行对账单 + 数据库流水）
        ↓
1. 解析层     读 Excel → 原始表（表头 + 样例行）
        ↓
2. 字段对应    银行侧 LLM 判断与数据库字段的对应 / 数据库侧固定配置 → 标准字段
        ↓
3. 标准化      生成「标准交易」列表（借/贷分列，不做归并）
        ↓
4. 匹配引擎(确定性)  逐笔 1:1 → 合并记账检测 → 未匹配
        ↓
5. 月度核对    月度借方总额 / 月度贷方总额，借对借、贷对贷
        ↓
6. 报告        Excel 标注表 + 文字总结
```

## 4. 标准交易模型（canonical）

无论来源，每笔流水统一为：

| 字段 | 说明 |
|---|---|
| `source` | `bank` / `db` |
| `date` | 交易日期（或记账日期） |
| `month` | 所属月份（由 date 派生，`YYYY-MM`） |
| `debit_amount` | 借方金额（≥0，无则 0） |
| `credit_amount` | 贷方金额（≥0，无则 0） |
| `counterparty` | 对方户名 / 往来方 |
| `counterparty_account` | 对方账号 |
| `summary` | 摘要 / 说明 |
| `remark` | 备注 |
| `voucher_no` | 凭证号（数据库侧） |
| `detail_index` | 明细序号（数据库侧） |
| `transaction_id` | 流水号（银行侧） |
| `balance` | 余额（银行侧） |
| `currency` | 币种 |
| `raw` | 原始行数据（用于追溯与回显） |

约定：

- 每笔流水 `debit_amount`、`credit_amount` **二者其一非零**（分别对应「借方」「贷方」），另一为 0。
- 辅助取值：`amount = debit_amount or credit_amount`；`direction ∈ {借, 贷}`。
- **不做方向归一化**：不引入带符号的净额，借/贷始终分列保留。

## 5. 字段对应（银行侧 LLM 判断 + 数据库侧固定配置）

### 5.1 银行对账单（格式不统一 → LLM 判断字段对应）

- 输入：银行对账单的表头列名 + 5–10 行样例行，以及数据库流水的字段定义（来自 §5.2 配置）。
- LLM 任务：判断银行对账单各字段与数据库对应字段的匹配关系（哪列对应借方金额、贷方金额、日期、对方、摘要…），输出标准字段映射。
- 标准字段为两边共用词汇：数据库侧由 §5.2 配置映射到同一套标准字段，从而确立「银行字段 ↔ 数据库字段」的对应。
- 输出：JSON 映射，如：

```json
{
  "date_column": "交易时间",
  "debit_column": "借方发生额（支取）",
  "credit_column": "贷方发生额（收入）",
  "counterparty_column": "对方户名",
  "counterparty_account_column": "对方账号",
  "summary_column": "摘要",
  "remark_column": "备注",
  "voucher_no_column": null,
  "detail_index_column": null,
  "transaction_id_column": "账户明细编号-交易流水号",
  "balance_column": "余额",
  "currency_column": "币种",
  "header_row_index": 0,
  "notes": ""
}
```

- 识别口径：**借/贷按财务含义识别**，哪列是「借方金额」、哪列是「贷方金额」，不写死字段名（`借方发生额`、乃至任意命名都可识别）。
- 用 Claude 结构化输出（JSON / tool use）。模型默认用经济档（Haiku/Sonnet，可配置）。
- 识别失败或置信度低 → 回退到「人工列映射」界面，或提示用户补充。

### 5.2 数据库流水（格式确定 → 固定配置映射）

- 数据库导出格式**视为确定**，用一份配置声明列对应关系（日期列、借方列、贷方列、对方列、摘要列、凭证号列、明细序号列…），默认按已确定格式填好。
- 改动时只改配置，不走 LLM。

## 6. 匹配引擎（确定性算法）

按月、按方向分组后执行，方向规则为**借对借、贷对贷**：

1. **逐笔 1:1 匹配**
   - 同月 + 同方向 + 金额完全相等 → 匹配。
   - 同月同方向出现重复金额时，用「日期距离最近」贪心消歧（如每月都有的 33400 公积金、30 短信费、6.14 电费）。
2. **合并记账检测**（见 §7）
   - 在 1:1 之后剩余的项里找「一条 = 多条之和」。
3. **未匹配**
   - 两边各自剩下的，分别列为「仅银行有」「仅数据库有」。

方向匹配说明：借对借、贷对贷。若两边约定相反（见 §11），由诊断逻辑提示，不自动翻转。

## 7. 合并记账检测

场景：系统对**同一往来方**的多笔流水合并记成一笔。检测与处理：

- 对 1:1 匹配后剩余的每一条数据库明细，寻找同月、同方向、金额之和恰好等于它的**多条**银行流水子集（子集大小限制 `K`，默认 8，可配置）。
- 命中 → 判定「合并记账」，给出拆分并标注。例如：

  > 合并记账：DB「归还委贷及利息」148,050,505.55 = 银行[归还委贷 140,000,000 + 利息 8,050,505.55]

- 反向（银行一条 = 数据库多条）也兜底处理，优先级低于正向。
- 用**子集求和（subset-sum，DFS + 剪枝，仅正数、以目标额封顶）**实现；存在多个候选子集时，优先选「对方户名/摘要更相似」的组合。
- 合并判断依据：金额和 + 同月 + 同方向为主，对方名称作为消歧辅助（两边命名体系不同，不能作为主键）。

## 8. 月度发生额核对

- 对两边都覆盖到的**每一个月**，分别统计：
  - 月度借方总额 = Σ `debit_amount`
  - 月度贷方总额 = Σ `credit_amount`
- 比对：银行借方总额 vs 数据库借方总额；银行贷方总额 vs 数据库贷方总额（**借对借、贷对贷**）。
- 借/贷差额**均为零** → 该月「一致」；任一非零 → 标「不一致」并给出差额。
- 两边月份范围不一致（样例里数据库到 8 月、对账单到 7 月）→ 只比对**重叠月份**，单边月份在总结里单独提示。

## 9. 报告输出

### Excel 标注表

- 逐笔并列展示银行侧与数据库侧，含：日期、借/贷、金额、对方户名、摘要、匹配状态。
- 匹配状态列：`已匹配` / `合并记账`（含拆分）/ `仅银行有` / `仅数据库有`。
- 附「月度汇总」sheet：每月借/贷总额、差异、是否一致。
- 合并记账行给出拆分标注。

### 文字总结（按严重度排序）

1. **月度总额不一致**（最严重）：列出月份、借方差额、贷方差额。
2. **未匹配项**：仅银行 / 仅数据库的笔数与明细（常与月度总额不一致同现）。
3. **合并记账提示**：列出每处拆分。
4. **全部对应**：无以上任何问题时明确提示「全部对应」。

## 10. Web UI

单页：

- 上传「银行对账单」+「数据库流水」两个文件。
- Claude API key 输入（存本地配置文件，不进代码/不提交）。
- 「开始对比」→ 展示总结 + 明细表 → 下载 Excel。

后端 FastAPI：

- `POST /api/compare`（multipart 上传）
- `GET /api/result/{id}`（JSON 结果）
- `GET /api/result/{id}/download`（Excel）

## 11. 已知问题与约定

- **样例数据的借/贷方向**：样例 `银行流水0603.xlsx` 用的是企业总账资产口径（借=收、贷=付），与银行对账单（借=付、贷=收）相反。工具按已确认的「借对借、贷对贷」执行，**不自动翻转**。
- **约定不一致诊断**：若月度核对出现「银行借方 ≈ 数据库贷方、银行贷方 ≈ 数据库借方」的对称错位，提示可能存在借贷口径不一致，建议检查数据库导出或调整配置。
- 数据库导出格式已视为确定，按实际口径固化默认配置；样例与真实导出口径不一致时改配置即可。

## 12. 错误处理

- 无 API key / 识别失败 → 降级人工列映射或友好报错。
- 金额非数字、日期解析失败、空行/合并表头 → 解析层清洗 + 记录，不中断整体。
- 两边月份范围不一致 → 只比对重叠月份并提示。
- 金额用 `Decimal`，避免浮点误差。

## 13. 测试策略

用三份真实样例（`活期账户明细….xls`、`银行流水0603.xlsx`、`活期账户明细_匹配结果.xls`）做固定夹具：

- **金标准测试**：先人工核对出正确结果（匹配笔数、合并拆分、月度总额差异），再写进断言。
- 单元测试：字段对应识别（mock LLM / 固定配置）、1:1 匹配、合并检测（子集求和）、月度汇总。
- 端到端：上传样例 → 断言输出 Excel 与总结符合预期。
